
### 関数リテラル

Clojureが新しい関数を作成する際に役立つもう1つの方法は、関数を定義するための代替の最小限の構文を提供することです。そのため、`fn`の洗練された行でさえ構文上のオーバーヘッドが多すぎると思えるような場合には、関数リテラルを使うことができます：`#`の後に関数本体が続き、通常の括弧でくくられるだけです。例えば、 `adventure?`の肝は関数リテラルとして書き直すと
 
```clojure
#(when (= (:genre %1) :adventure) %1)
```

関数リテラルには名前付き引数がないことに注意してほしい。その代わり、第一引数には`%1`、第二引数には`%2`といった具合に、いかにもシェルスクリプトらしい記法が使われる。つまり、数値を2倍にする関数が必要な場合は、partialを使うか、次のようにする：

```clojure
#(* 2 %1)
```

また、3つの数字を足し合わせる関数が必要な場合は、このように作るかもしれない：

```clojure 
#(+ %1 %2 %3)
``` 

関数リテラル、または「ラムダ」と呼ばれるものについては、いくつか覚えておくべきことがあります。1 つ目は、関数リテラルと `fn` は全く同じ種類のもの (関数値) を生成します。

第2に、Clojureは、文字どおり定義された関数が取る引数の数を、関数本体の中で最も大きい番号の引数から推測することを覚えておいてください。したがって、"double the number "関数をこのように修正すると、次のようになります：

```clojure
#(* 2 %11) 
```

この場合、11個の引数を取り、最初の10個を無視する（非常に不便な）関数が出来上がってしまいます。

最後に、関数リテラルには、引数が1つの関数を作成するという非常によくあるケースを直接対象とした特別な機能があります。作ろうとしている関数が1つの引数を取る場合、1つだけの引数には、数値のない普通の `%` を使うことができます。つまり、今回の数値倍増関数の最小バージョンは以下のようになる：

```clojure
#(* % 2)
```


`defn`で本格的な名前付き関数を定義するか、簡素化された`fn`を使うか、あるいは完全に削ぎ落とされた関数リテラルを使うかのトレードオフは、ソフトウェアエンジニアリングではおなじみの選択のひとつだ。関数を再利用するのであれば、ぜひdefnを使って名前をつけましょう。関数に名前をつけることは、その名前があなた（や後から来た人たち）が複雑なコードを理解する助けになる場合にも意味があります。また、コードを視覚的に分割するために、長い関数には `defn` を使いたいだろう。

一方、`fn`と関数リテラルは、短い関数を1回だけ使うときや、クロージャを利用して値を取得したいときに便利です。

`fn`と関数リテラルのどちらを選ぶかは、複雑さと引数の数で決まります。本当に短くて単純な関数の場合は、関数リテラルを使うようにしましょう。 例えば、数値を2倍にする関数が必要なら、ぜひとも `#(* % 2)` と書いてください。逆に、もっと長い関数、特にいくつかの引数を取るような関数は `fn` にしましょう。例はさておき、本当に`%11`を持つ関数リテラルを書く人はいません。
