## 4. 用語メモ・誤解しやすい点

確定用語集は構成工程の成果物。ここでは調査メモとして残す。

### 4.1 用語（日英併記の候補）

| 日本語（案） | 英語 / 記号 | 一言定義（調査メモ） |
|--------------|-------------|----------------------|
| マクロ展開 | macroexpansion | コンパイル（または評価準備）前にフォームを別フォームへ変換すること |
| 構文引用 | syntax-quote (`` ` ``) | 名前空間修飾付きのテンプレート用クォート |
| アンクォート | unquote (`~`) | 構文引用内で評価結果を埋め込む（「反引用」は使わない。準引用は `` ` ``） |
| スプライシング | unquote-splicing (`~@`) | 列を親リストに繋ぎ込む |
| 自動 gensym | auto-gensym (`foo#`) | 同一構文引用内で安定した一意シンボル |
| 変数捕獲 | variable capture | 展開結果が意図せず既存束縛を参照／束縛してしまうこと |
| 意図的捕獲 | intentional capture / anaphoric | `it` のような暗黙束縛を狙って作ること（賛否あり） |
| 二重評価 | double evaluation | 同じ入力フォームが展開結果で複数回評価されること |
| 特殊形式 | special form | マクロでも関数でもない、評価規則が組み込みの構文 |
| 衛生 | hygiene | 名前衝突を防ぐ性質。Clojure は自動衛生が限定的で著者責任が大きい |

### 4.2 学習者がつまずきやすい点（本文で先回りする）

1. **マクロの引数は「もう評価された値」だと思い込む** → 未評価フォームが渡る  
2. **`'` と `` ` `` を同一視する** → 名前空間修飾と `~` の有無が違う  
3. **`macroexpand` と実行結果を混同する** → 展開はコードの形、実行は別  
4. **`eval` でマクロの代わりを済ませようとする** → タイミングも安全も違う  
5. **gensym なしで `let` 束縛名をベタ書きする** → 変数捕獲  
6. **展開内でユーザー式を二度書く** → 二重評価（副作用・性能）  
7. **マクロを高階関数のように渡そうとする** → 第一級ではない  
8. **データで足りる DSL をマクロにする** → ツール・エラー・合成が悪化しやすい  
9. **`&env` を `macroexpand` の実験だけで理解した気になる** → 展開コンテキスト差あり（要検証メモ）  
10. **CLJS で JVM と同じ置き方を仮定する** → マクロの名前空間配置が違う（補章）

### 4.3 要検証リスト（執筆前に REPL で確定）

- [x] `&env` が `macroexpand` / 実際のコンパイルでどう見えるかの最小再現 → 実展開では locals あり、`macroexpand-1` 単独では空になりうる  
- [x] `macroexpand-all`（walk）が `#()` や特殊形式近傍でどこまで展開するか → ネストマクロは展開、`#()` はリーダー済み、`let`→`let*`  
- [x] `foo#` がネストした構文引用でどう共有／分離されるか → 同一 `` ` `` 内共有、別／ネストは新スコープ  
- [x] 現行 Clojure バージョン（本書が固定する版）の確認と明記 → **1.12.x**（実行 1.12.1）／推奨 JDK **21**

`記述範囲.md` の6本を、調査観点で一段具体化する。

| # | 題材 | 必須で見せる展開・罠 | 参照・類似 | 初版優先度 |
|---|------|----------------------|------------|------------|
| 1 | `unless` / `when-let` 再実装 | 評価順、束縛＋条件 | `clojure.core` の `when-let` | 高（通読版の核） |

| 4 | バリデーション付き `defn` 風 | 定義マクロ、良いエラー | `defn` の構造観察 | 中 |
| 5 | 小さな HTML or ルーティング DSL | `~@`、ネスト | Hiccup / Compojure と対比 | 中（DSL章と共用） |
| 6 | 状態機械 or クエリ（入口のみマクロ） | マクロ境界、内部はデータ | HoneySQL 思想 | 中〜低（厚くしない） |

### 5.1 章末ミニ演習の種（プロトタイプへ送る）

- 読む: `and` / `or` / `when` のソースを読み、展開を予想してから `macroexpand-1`  
- 直す: 意図的に壊した二重評価マクロを修正する  
- 書く: 1引数の `def-` 風（プライベート定義の糖衣）を薄く実装する  
- 判断: 「このAPIはマクロであるべきか」短文で理由を書く（模範はチェックリスト形式）
