## 2.1 動機

マクロを理解する鍵は、「プログラムのテキスト」と「評価された値」のあいだに、**フォームというデータ**があることだ。マクロはそのデータを受け取り、別のフォームを返す。

## 2.2 段階

おおまかには次の流れである。

1. **Read** — テキスト → データ（リスト・シンボル・リテラル等）  
2. **Macroexpand** — マクロ呼び出しを、別のフォームへ書き換え  
3. **Compile / Eval** — 実行可能な形へ／値を得る  

「いつ形が変わるか」を意識すると、`macroexpand` の結果と実行結果を混同しにくくなる。

## 2.3 フォームを手で組む

```clojure
(def form (list '+ 1 2))
(first form)  ; => +
(rest form)   ; => (1 2)
```

これは「コードをデータとして触っている」状態である。  
`eval` すれば `3` になるが、**`eval` はマクロの代わりではない**。タイミングも、必要な文脈も、安全モデルも違う。本書ではデモ以外で `eval` に頼らない。

## 2.4 特殊形式・マクロ・関数

**表 2.1** 呼び出しの種類と評価

| 種類 | 引数の評価 | 拡張 |
|------|------------|------|
| 特殊形式 | 独自規則 | 言語組み込み |
| マクロ | まず展開（引数は未評価のフォーム） | ユーザが追加可 |
| 関数 | すべて評価してから本体 | ユーザが追加可 |

エラーや奇妙な挙動に出会ったら、まずこのどれかを切り分ける。

## 2.6 まとめ — 関数でよいか？

データ変換としてコードを触る必要がなければ、無理にフォームを組むな。  
マクロは「評価前の形」を扱う道具であり、通常のビジネスロジックの置き場ではない。
