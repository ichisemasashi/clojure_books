## 7.1 動機

自分で書く前に、`clojure.core` の短いマクロから **型を盗む**。  
読み方は第5章と同じく「予想 → `macroexpand-1` → メモ」である。

## 7.2 `when`

```clojure
(macroexpand-1 '(when true :a :b))
;; => (if true (do :a :b))
```

盗む点: 複数ボディを `do` にまとめる薄い糖衣。

## 7.3 `or`（短絡）

```clojure
(macroexpand-1 '(or false nil :ok))
;; => (let [or__auto__ false]
;;      (if or__auto__ or__auto__ (or nil :ok)))
```

盗む点: 一度束縛してから分岐し、**残りの `or` を再帰的に展開**する。二重評価を避けつつ短絡する。

## 7.4 `when-let`

```clojure
(macroexpand-1 '(when-let [x (first [1])] (inc x)))
;; => (let [temp__auto__ (first [1])]
;;      (when temp__auto__
;;        (let [x temp__auto__] (inc x))))
```

盗む点: テスト式を一時束縛し、真のときだけユーザの名前に渡す。第13章のケース A で再実装する。

## 7.5 通読版での止め方

ここでは3つに留める。  
完全版では `cond` / `->` / `with-open` などを同様の型で追加し、ソースの版と行を明記する。

## 7.6 演習

1. **読む:** 上記3マクロについて「盗む点」を各1行で書け。  
2. **判断:** どれが関数にできないか、一言で述べよ。

## 7.7 まとめ — 関数でよいか？

`when` や `when-let` がマクロなのは、評価制御と束縛が本質だからである。  
同じ見た目を関数で無理に真似ると、呼び出し側が thunk だらけになる。
