## 5.1 動機

マクロのデバッグで最初にやることは、実行結果をいじることより **展開結果を見ること** である。

## 5.2 道具

| 関数 | 意味 |
|------|------|
| `macroexpand-1` | 先頭がマクロなら **一段だけ** 展開 |
| `macroexpand` | 先頭がマクロのあいだ繰り返し（**入れ子の内側は見ない**） |
| `clojure.walk/macroexpand-all` | 木を歩き、内側も展開（限界あり） |

```clojure
(macroexpand-1 '(when true 1 2))
;; => (if true (do 1 2))

(clojure.walk/macroexpand-all
  '(when true (when false 1)))
;; => (if true (do (if false (do 1))))
```

## 5.3 予想 → 展開 → 差分

ワークシートの型:

1. 手で展開形を書く  
2. `macroexpand-1` する  
3. 差分を一言でメモする  

この型を、後述の第7章「標準マクロを読む」でも使う。

## 5.4 `&form` / `&env`（通読版は存在だけ）

`defmacro` 内では特殊な名前 `&form`（呼び出し全体）と `&env`（局所束縛の情報）が使える。  
通読版では「ある」と知るだけでよい。`macroexpand` だけで `&env` を覗くと空に見えることがあり、実コンパイル時と差が出る（[`notes/核検証メモ.md`](../notes/核検証メモ.md)）。

## 5.5 罠: 展開確認用フォームの作り方

`` `(my-macro [x ...]) `` のように **構文引用で引数まで書く** と、`x` が先に名前空間修飾され、展開結果が本番とずれる。  
確認は次のようにする。

```clojure
(macroexpand-1 (list `my-macro '[x (first [1])] '(inc x)))
```

## 5.6 演習

1. **読む:** `(or false nil :ok)` の展開を予想してから照合せよ。  
2. **書く:** 自作 `unless` の展開テストを1本書け（`=` でフォーム比較でよい）。

## 5.7 まとめ — 関数でよいか？

展開を見る習慣はマクロ専用の技能である。  
関数のデバッグに `macroexpand` は不要——そのときは値とスタックを見よ。
