# 選択ケース／付録候補メモ（次版）

確定版 v1.0 では本文化せず、レポート形式のたたき台として置く。

## ケース D — 定義マクロ（薄い）

**仕様例:** `(defroute-lite name path handler)` が  
`(def name {:path path :handler handler})` 相当を生成する。

**盗む点:** 名前を定義に載せる糖衣。評価制御は不要なことが多い。  
**控える判断:** データリテラル＋`def` で足りるならマクロにしない（第11・14章）。

## ケース E — 小さな DSL

**仕様例:** 第11章の `defroutes-lite` を拡張し、ネスト経路だけ追加する。  
**盗む点:** 展開時にデータへ落とす境界。  
**控える判断:** HoneySQL / Hiccup 型（データが主）と比較する。

## anaphoric（意図的捕獲）— 賛否メモ

- **賛成側:** 短い DSL で `it` が読みやすい場面がある。  
- **反対側:** 暗黙束縛はツール・リネーム・入れ子で壊れやすい。本書の推奨は非推奨（第6章）。  
- **折衷:** 明示束縛を既定にし、anaphoric は実験用名前空間に隔離する。

詳細実装は読者レポートまたは次版本文で扱う。
