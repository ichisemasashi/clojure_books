# 載せない失敗例メモ

プロトタイプ／本文に **完成例として載せない**（または「壊れた例→直し」専用にする）ものの記録。

| ID | 例 | なぜ載せない／どう扱うか |
|----|-----|--------------------------|
| F1 | `bad-time-double`（`ch06-hygiene`） | 二重評価。本文では「直し」用に短く出し、完成 API としては載せない |
| F2 | `broken-twice`（演習） | 演習の罠。解答の `once-add` と対にする |
| F3 | anaphoric な `it` 束縛マクロ | 意図的捕獲。通読版では深入りしない。賛否付きで完全版候補 |
| F4 | `eval` でマクロの代わりをする例を「推奨」扱い | タイミング・安全が違う。第2章で距離を取るだけ |
| F5 | 名前空間修飾されていないベタ `let` 束縛名のコピペ宏 | 変数捕獲の温床。gensym なしの完成例は出さない |
| F6 | ケース A の展開確認を `` `(when-let-lite [x ...]) `` で書く | 引数の `x` が先に修飾され誤った展開になる。`list` + クォートを使う（検証で踩み済） |

## 方針

- 失敗例は **意図をラベルしたうえで** 出す（「これは壊れている」）
- 通読版の完成マクロは `unless` / `when-let-lite` / `good-time` / `labeled-time` に限定
- 完全版で F3 等を扱う場合も、推奨デフォルトにはしない
